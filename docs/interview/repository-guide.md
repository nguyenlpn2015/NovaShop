# Repository Guide

The platform, taught end to end. Every section points at the file it describes.

---

## 1. Introduction

NovaShop is a two-tier web application used as the payload for a platform. The application is
deliberately trivial — FastAPI and Next.js, no business logic, **zero database tables**. The
platform around it is the subject.

**What it runs on:** one Ubuntu 22.04 node, `10.10.1.45`, k3s v1.33.13, 8GB RAM, 28GB disk.

**What is live:** three environments behind Traefik with real Let's Encrypt certificates at
`novashop.smartdev.vn`, `staging.`, and `dev.`.

**Measured at v1.0.0:** 12/12 Argo CD Applications Synced and Healthy, 31/31 Prometheus
targets up, 14 alert rules with 14 runbooks, 94 automated pre-merge checks, and 117
documents with 0 broken links. (The document count grows; the release figure is 117.)

## 3. Architecture

### The five subsystems

**Delivery.** Pull request runs five checks. Merge to `main` runs the *same reusable
workflow* inside the release job graph, then builds, scans, and only then pushes.

**Desired state.** A second repository. Every reference to `NovaShop` is a 40-character SHA,
verified to be an ancestor of `main` and to correspond to images that exist in GHCR.

**Edge.** Traefik terminates TLS with cert-manager certificates over HTTP-01. TLS arrives in
three phases so a fresh cluster is never blocked on issuance.

**Runtime.** Three environments from one Helm chart and three values files, generated by an
ApplicationSet. PostgreSQL and Redis run **on the node**, not in the cluster.

**Observability.** Prometheus scrapes 31 targets. Loki holds logs from an Alloy DaemonSet.
Fourteen alerts, each linked to a runbook CI proves exists.

### The constraints that explain everything

Memorise this table. Almost every "why did you…" question resolves to one row.

| Constraint | Consequence |
|---|---|
| **One node** | No rescheduling. Recovery is a procedure, not an assumption about redundancy |
| **k3s uses SQLite, not etcd** | Backup is a file copy; the write path is a single point of failure |
| **`local-path` is the only StorageClass** | Volumes are node-local and cannot outlive the node |
| **Let's Encrypt: 5 duplicate certs / 168h** | TLS is phased; recovery restores certs *before* reconciling; the runbook forbids deleting a Certificate to "force a retry" |
| **Memory limits ~150% of allocatable** | Deliberate overcommit; every container declares requests and limits, enforced by a gate |
| **PostgreSQL and Redis outside the cluster** | Reached over the pod network, so one alert covers three distinct faults |

## 4. Technology Choices

### k3s — [ADR 002](../../adr/002-kubernetes-distribution.md)

**Why:** single binary, SQLite instead of etcd, Traefik and `local-path` bundled. Backup is a
file, not an etcd snapshot — which matters when recovering under pressure.

**Rejected:** kubeadm (etcd on one node is a memory cost and the component most likely to need
expert intervention); managed Kubernetes (hides bootstrap, recovery, and node concerns — the
substance of the project); MicroK8s (snap lifecycle is harder to script idempotently); k0s
(credible; rejected on ecosystem familiarity, and that is the weakest argument in the ADR).

**Trade-off accepted:** no HA, SQLite as a single point of failure, Traefik versioned by k3s,
and control-plane metrics needing flag changes plus a restart.

### GitOps — [ADR 003](../../adr/003-gitops-delivery.md)

**Why:** the desired state must exist outside the cluster to be replayable, and CI must not
hold cluster credentials.

**Rejected:** push-based CI deployment (long-lived cluster-admin credentials in the place with
the largest attack surface; no self-heal); one repository (couples the lifecycles — every image
build becomes a potential deployment).

**Trade-off accepted:** two merges per release. That is the feature — the second merge is where
a human decides a verified image should go live.

### Argo CD — [ADR 005](../../adr/005-gitops-controller.md)

**Why:** multi-source Applications compose a chart from one repository with values from
another; `AppProject` gives an enforceable resource whitelist; sync waves give ordering; the
UI answers "what differs from Git" instantly for a single operator.

**Rejected:** Flux — genuinely strong, smaller footprint, cleaner controller-per-concern
design. Rejected because its cross-repository `HelmRelease` composition is less direct, and
because it has no `AppProject` equivalent — that boundary would need Kyverno, which means
adding a technology to get a property Argo CD includes.

### Helm and Kustomize — [ADR 006](../../adr/006-helm-and-kustomize.md)

**Why both:** Helm for anything *installed* (one chart, three environments, parametric
variation). Kustomize for *composing and ordering* Argo CD objects into the three edge phases.

**Rule:** Kustomize never patches rendered chart output. Helm never expresses phase
composition.

**Rejected:** Kustomize-only (a committed render is a fork); Helm-only (phase ordering as
template conditionals produces output nobody can predict); Jsonnet/cdk8s (solving a problem
this platform does not have).

### Traefik — [ADR 007](../../adr/007-ingress-controller.md)

**Why:** it ships with k3s and works. The real question was whether to disable it.

**The decisive requirement:** the edge must serve plain HTTP before any certificate exists,
because HTTP-01 needs port 80 to reach this node. An ingress that cannot usefully serve
without TLS makes the first certificate impossible to obtain.

**Rejected:** ingress-nginx (replacing a working bundled component for capabilities not used);
**Traefik's own ACME** — the interesting one. It would remove cert-manager entirely, but stores
ACME state in a pod-local file. cert-manager keeps certificates in Kubernetes Secrets, which
back up and restore like anything else — and restoring them *before* reconciliation is what
keeps recovery from spending the rate-limit budget.

### GitHub Actions — [ADR 008](../../adr/008-ci-platform.md)

**Why:** the repositories are on GitHub, and the `platform` job needs both checked out
together for cross-repository revision validation.

**The key design:** `validation.yml` is `workflow_call` only. `ci.yml` calls it on pull
requests; `release.yml` calls **the same file** with `publish` declaring `needs: validate`.

**Rejected:** a separate release triggered by CI completion — this was the obvious first
design, and it can only *narrow* the race, never remove it. Any check-then-act across two runs
has a window. One job graph has none.

Also rejected: Jenkins and Argo Workflows/Tekton — CI that runs on the cluster cannot build the
fix for a broken cluster.

### Prometheus, Grafana, Loki, Alertmanager — [ADR 009](../../adr/009-observability-stack.md)

**Rejected:** `kube-prometheus-stack`, the default recommendation. Its resource requests do not
fit alongside PostgreSQL, Redis, and Loki on 8GB without trimming away its advantage — and its
~100 alert rules would be *inherited*, mostly for multi-node conditions that cannot occur, none
carrying a runbook. **Fourteen rules whose expressions were each evaluated against live data is
better evidence than 100 that arrived in a chart.**

Also rejected: Prometheus Operator (CRDs and a controller for one instance; annotation-based
discovery made a real failure mode *visible*); Loki scalable mode (its two memcached caches
alone exceed free memory).

### Grafana Alloy — [ADR 004](../../adr/004-log-collection-agent.md)

Replaces **both** Promtail and the OpenTelemetry Collector from the original scope — one fewer
technology, not one more. Promtail reached end of life in March 2026.

### Terraform — [ADR 012](../../adr/012-terraform-scope.md), [013](../../adr/013-terraform-kubernetes-boundary.md), [014](../../adr/014-terraform-gitops-handover.md)

Non-cloud. Codifies GitHub, DNS, the node, datastores, k3s, and the Argo CD seed.

**The boundary:** Terraform manages what Argo CD does not reconcile, and **never** an object it
does. With `selfHeal` on, a Terraform-managed Deployment is reverted every three minutes and
`plan` never converges.

## 5. Important Design Decisions

### Phased TLS

Three phases — `http`, `tls-baseline`, `tls-enforced` — driven entirely by the five-duplicates
rate limit. Certificate issuance cannot sit inside anything that retries.

**The phase is detected from live cluster state** by `scripts/lib/edge-phase.sh`, never
assumed, because `verify.sh` asserts different properties per phase and a script that can be
told which phase it is in can be told the wrong one.

**Rollback unwinds HSTS with `max-age=0` first.** Dropping straight to HTTP leaves every
previous visitor unable to reach the site with no error they can click through.

### Three health endpoints

| Endpoint | Consults | Used by |
|---|---|---|
| `/health` | nothing | legacy |
| `/live` | nothing | liveness probe |
| `/ready` | PostgreSQL **and** Redis | readiness probe |

`/live` deliberately checks no dependency. A liveness probe that fails when the database is
unreachable **restarts a healthy process** and turns a datastore outage into a crash loop.

**The trap:** `/ready` checks that PostgreSQL is *reachable*, not that it holds data. Skip the
data restore during recovery and pods go Ready, Applications report Healthy, no alert fires,
and the application serves an empty database.

### Secrets outside Git — [ADR 010](../../adr/010-secret-management.md)

Runtime credentials in `/root/.novashop-platform.env`, root-owned, 0600. Two Kubernetes
Secrets created out of band.

**Rejected:** Sealed Secrets, SOPS, Vault, External Secrets — every one moves the bootstrap
problem to a key that must survive a node rebuild, on node-local storage. And **Terraform state
stores values in plaintext**, so managing secrets there would make the platform *less* secure
than a 0600 file.

**Accepted cost:** the desired state is incomplete. A rebuild from Git alone produces workloads
that cannot authenticate.

## 7. CI/CD

Three workflows: `ci.yml`, `release.yml`, `validation.yml`.

`validation.yml` is `workflow_call` only, with six jobs: `backend`, `frontend`, `security`,
`platform`, `terraform`, `container-images`.

### The three guarantees, each structural

**Release cannot race CI** — both call the same reusable workflow inside one job graph.

**An unscanned image cannot publish** — inside `publish`: build loads locally → Trivy scans →
*then* log in to GHCR → push. Registry credentials are not acquired until the scan passes.

**`latest` moves only after everything** — a separate job with `needs: publish`.

### Details worth knowing

- Every third-party action pinned to a **full commit SHA** with the version in a comment
- `fail-fast: false` — a frontend CVE was cancelling the backend job across three blocked
  releases, hiding whether the backend was clean
- Runtime version alignment: Node major and Python minor must match across Dockerfiles,
  workflow env vars, `engines.node`, `@types/node`, `requires-python`

**Known rough edge:** `ci.yml` triggers on both `pull_request` and `push`, producing duplicate
runs. Documented, not fixed.

## 8. GitOps

### Revision discipline

`scripts/validate-gitops-revisions.sh` fails a pull request unless every reference is a
40-hex SHA, **an ancestor of `origin/main`**, both components come from one commit, no tag is
`latest`, and **both images exist in GHCR** — checked with an anonymous token.

That last one earns its keep: a pin to a commit whose release failed renders and validates
perfectly and produces `ImagePullBackOff`.

**Deliberate exception:** `novashop-root` and the ApplicationSet's own repository track `main`.
Pinning the root Application would mean no GitOps change could ever take effect.

### Phases and waves

| Phase | Contains |
|---|---|
| `http` | ApplicationSet, three environments |
| `tls-baseline` | AppProject, cert-manager, Certificates, the whole observability stack |
| `tls-enforced` | Redirect and HSTS |

Sync waves `-30` (AppProject) → `-20` (cert-manager) → `-15` (Prometheus, ahead of what it
observes) → `0` (Certificates) → `10` (applications).

### Two traps

**The `AppProject` whitelist is enforced at sync time.** A manifest can render, validate, merge,
and *then* be refused. Loki's `StatefulSet` did. The response was a pre-merge gate.

**`ServerSideApply` changes what "diff" means.** Sync status compares `predictedLiveState`
against `normalizedLiveState` — a dry-run, not the rendered manifest. `helm template | diff`
reports zero differences on a permanently OutOfSync Application.

## 9. Terraform

Seven layers, each a root module with its own state and schema.

| Layer | Manages | Provider |
|---|---|---|
| `0-node` | packages, swap, sysctl, UFW | built-in |
| `1-datastores` | PostgreSQL roles/grants, Redis config | `cyrilgdn/postgresql` |
| `2-k3s` | version, server arguments | built-in |
| `3-github` | repositories, rulesets, Dependabot | `integrations/github` |
| `4-dns` | Cloudflare A records | `cloudflare/cloudflare` |
| `5-cluster` | `argocd` namespace, read-only ClusterRole, prerequisites | `kubernetes` |
| `6-gitops` | Argo CD, AppProject, root Application, repo registration | `kubernetes` |

**State:** `pg` backend in the PostgreSQL already on the node — already backed up, gives real
locking, adds no infrastructure. Ordering cost: PostgreSQL must be restored before Terraform
runs at all.

**Import, never create.** Every resource exists. Acceptance gate is an **empty plan**.

**Be honest:** five of seven layers manage nothing. 74 variables, 48 outputs, 6 resources, and
no output has a consumer. [TERRAFORM_AUDIT.md](../TERRAFORM_AUDIT.md) scores it 3.4/5.

## 10. Kubernetes, Helm, Traefik, cert-manager

**Helm chart** — eight templates: two Deployments, two Services, ConfigMap, Ingress, Namespace,
and four NetworkPolicies in one file. No HPA, no PDB, no topologySpreadConstraints — all
meaningless on one node, and their absence is deliberate.

**Replicas:** dev 1, staging 2, production 3. Three replicas on one node demonstrates scaling
mechanics, not capacity, and is why memory limits sit near 150%.

**Traefik** — routes by `Host`; four names on one address. Metrics on **pod port 9100 only**;
the Service exposes `web` and `websecure`. `websecure` is named explicitly on production
Ingress objects, because leaving it implicit can bind a router to `web` and serve plain HTTP
with nothing reporting an error.

**cert-manager** — v1.21.0, `ClusterIssuer` `letsencrypt-production`, HTTP-01. Renews at ~60
days of a 90-day lifetime, so `CertificateExpiring` fires at **21 days**: reaching it proves
renewal has been failing for over a week.

## 11. Observability

### Metrics

31 targets. Retention 7 days **and** 2GB — a size cap as well as time, because on one shared
disk time alone bounds nothing.

**Known duplication:** Traefik is scraped twice, by the dedicated job and by the chart's
default annotation-based `kubernetes-pods` job. Seven duplicate series. Edge alerts pin
`job="traefik"`.

### Logs

Alloy DaemonSet → Loki, single binary, filesystem, 120h retention.

Container logs read **through the Kubernetes API**, not host paths. Labels kept low
cardinality — anything request-derived goes in the log line, because one high-cardinality
label fills a 2Gi volume in hours.

**Journal needs `relabel_rules`, not `stage.labels`** — the latter promotes from the extracted
map, which is empty for journal input.

### Alerting

14 rules, 7 groups, each with a `runbook_url` **CI resolves to a real file**. Grouped by
`alertname` and `namespace`. `repeat_interval` 12h — shorter trains people to mute the channel.
`NodeDown` inhibits everything else for that instance.

**Alerts route nowhere.** One receiver, no destination. Delivering needs a credential this
repository does not hold and an on-call decision.

### Tempo and OpenTelemetry — the honest answer

**Tempo is not deployed. OpenTelemetry is instrumented and disabled.**

`backend/app/observability/tracing.py` instruments FastAPI, `asyncpg`, and `redis` with
`ParentBased(TraceIdRatioBased)` sampling, guarded imports, and `/metrics`, `/live`, `/ready`
excluded. It activates only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. Nothing sets it.

**Why** — [ADR 011](../../adr/011-distributed-tracing.md): the backend has no business
endpoints and the frontend calls it from the browser. A trace today contains `GET /ready`, one
`asyncpg SELECT 1`, and one Redis `PING`. That demonstrates plumbing, not tracing.

**What would change it:** a business endpoint spanning both datastores; a server-side rendering
path; or a decision to expose an authenticated public OTLP endpoint for browser RUM.

**When deployed, Alloy terminates OTLP** — it already runs and already performs that role.

## 12. Security

| Control | State |
|---|---|
| Container user | non-root, uid 10001, numeric |
| Root filesystem | read-only |
| Privilege escalation | disabled |
| Capabilities | `drop: ["ALL"]` |
| seccomp | `RuntimeDefault` |
| SA token | not mounted |
| Pod Security Admission | `restricted`, **demonstrably enforcing** |
| NetworkPolicy | default-deny ingress in application namespaces |
| Images | Actions and Argo CD manifest pinned by digest; scan before push |
| Secrets | never in Git, never in Terraform state, enforced by a `check` block |

**Proof PSA enforces:** the author's own `kubectl run busybox` diagnostic pod was rejected for
four separate violations.

**NetworkPolicy enforcement was proven before any policy was written** — kube-router running,
123 iptables chains, and a deny-all took a probe pod from REACHABLE to BLOCKED.

**One rule admits the node network deliberately:** kubelet probes originate on the node, not
from a pod. A namespace-only rule takes every replica NotReady the instant it applies.

**Open:** node credentials not rotated, no egress restriction, `observability` and
`cert-manager` unprotected, no image signing.

## 13. Recovery

**Ordering, non-negotiable:**

1. Preconditions — all checked, **nothing changed**
2. Environment loaded
3. Cluster rebuilt
4. **Certificates restored** — before Argo CD, or cert-manager spends one of five
5. **Datastore contents restored** — verified first
6. Argo CD reconciles from Git
7. `verify.sh` against the **detected** edge phase

**Backup tiering.** The on-node set is 27MB and volumes are 550MB, but the part that genuinely
cannot be regenerated is **21 KB**: 3 TLS Secrets, 2 ACME account keys, a PostgreSQL dump, the
environment file.

**Never `cp` the k3s SQLite file.** k3s writes continuously; a byte copy can capture a
half-written page and produce a file that looks fine and is corrupt. Use `sqlite3 .backup`.
k3s ships snapshots for **etcd only**.

**Validated:** database recovery 137 rows with identical content md5; GitOps recovery in 5
seconds. **Not validated:** the full sequence on a replacement node. RTO 30–45 minutes is an
estimate and should be called unknown.

## 14. Production Hardening

What was done, and what was deliberately not.

**Done:** PSA `restricted`, non-root containers, default-deny ingress trialled with a control
group, least privilege proven by attempting a denied write, scan-before-push, digest pinning,
inotify limits raised.

**Not done, with reasons:** egress restriction (an egress rule that gets the datastore path
wrong takes every replica unready — a hardening change causing an outage); network policies in
`observability` (Prometheus needs broad egress to scrape); image signing; alert routing.

## 15. Common Failures

The ones this platform actually hit. Each is a good interview story.

| Failure | Why it was invisible |
|---|---|
| Scrape annotation named the Service port | Six replicas refused connections; nothing unhealthy, metric simply absent |
| Traefik metrics only on the pod | Endpoints job renders, validates, deploys, collects nothing |
| `helm template \| diff` under `ServerSideApply` | Reports zero differences on a permanently OutOfSync Application |
| `recover.sh` grepped `^DATABASE_URL=` | File declares `export DATABASE_URL=`; recovery aborted on a healthy platform |
| `pg_monitor` on PostgreSQL 14 | `CREATE` on `public` is granted to `PUBLIC`; PG15 removed it |
| inotify exhaustion at 128 instances | A workload that cannot create a watcher keeps running and stops noticing changes |
| kube-router rule propagation race | A probe pod ran `wget` before its rules existed — and gave the *expected* answer |
| Stacked PR merged into its base | GitHub said MERGED; 1,091 lines landed nowhere; CI green |

## 16. Lessons Learned

Full detail: [LEARNING_LOG.md](../LEARNING_LOG.md) — 16 defects.

**Run it.** Every defect above passed review. `recover.sh` took thirty seconds of execution to
expose and had survived the entire project.

**A green dashboard means nothing is *reporting* a problem.** On this platform that has
repeatedly not meant nothing is wrong.

**An inconclusive experiment is not a negative result.** Reading "unchanged" from a
self-healed patch discarded a working fix.

**Distrust a test that agrees with you.** The NetworkPolicy race produced the isolation result
I wanted, by the same broken mechanism that produced an obviously wrong one.

**Documentation drifts toward optimism.** Two documents claimed a backup existed. Someone reads
that and stops looking — which is how the database went unprotected.
